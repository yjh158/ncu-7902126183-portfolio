## 一、这个仓库是做什么的？

这是本门课程的个人学习档案（Portfolio）。简单说，它像一个**「成长档案袋 + 游戏存档」**：

- **档案袋**：16 周的每一次实验、每一份代码、每一篇实验报告都按周归档在这里，期末可以直接翻出来复盘。
- **游戏存档**：每一次 `Commit` 就是一次「存档点」。写崩了？随时读档回到上周能跑通的版本。
- **公开简历**：仓库是 Public 的， recruiter / 老师打开链接就能看到你的完整学习轨迹，比简历上写「熟悉 Python」有说服力得多。

## 四、每日三步走（写给零基础的自己）

```bash
# ① 拉取远程最新内容（开工前先做）
git pull

# ② 把改动「打包存档」（写完一段代码就做）
git add .
git commit -m "week-01: 完成实验一的数据清洗"

# ③ 把存档同步到 GitHub（收工前做）
git push
```

**口诀：`pull` 开工 → `add` + `commit` 存档 → `push` 上传。**

## 五、名词大白话小抄

| 术语 | 一句话解释 | 生活类比 |
| :--- | :--- | :--- |
| **仓库（Repository / Repo）** | 存放这个项目所有文件和全部历史版本的文件夹 | 你的**专属网盘文件夹**，而且自带「历史版本」功能 |
| **Git** | 装在电脑上的版本管理软件，负责记录每一次改动 | 装在电脑里的**「时光机」** |
| **GitHub** | 把 Git 仓库放到云端的网站 | 存放时光机的**云端服务器 + 个人主页** |
| **`.gitignore`** | 一份「黑名单」，写上它，Git 就当这些文件不存在 | **垃圾桶过滤器**：草稿、密码、缓存全被拦下，不上传 |
| **`git init`** | 在当前文件夹开启 Git 追踪 | 给普通文件夹**装上时光机**（只需做一次） |
| **`git add`** | 把改动放进「待存档区」（暂存区） | 把要寄的东西**装进快递箱** |
| **Commit（提交）** | 把暂存区的改动正式保存为一个版本，附带一句说明 | **拍一张快照 / 打一个游戏存档点** |
| **`git push`** | 把本地的存档上传到 GitHub | 把本地相册**备份到云端** |
| **`git pull`** | 把 GitHub 上的最新内容下载到本地 | 从云端**把相册同步回来** |
| **README.md** | 项目的说明书，打开仓库首页就会自动显示 | 这个档案袋的**封面 + 目录 + 使用说明** |
| **Markdown（.md）** | 一种极简排版语法，`#` 是标题，`-` 是列表 | 写文档的**「轻量版 Word」** |

## 六、注意事项

1. **不要把密码、API Key、Token 写进任何文件**，`.gitignore` 已经帮你拦截常见密钥文件，但仍需自己留心。
2. 大文件（数据集、压缩包、视频）不要直接提交，会被 `.gitignore` 忽略；需要时用 Git LFS 或云盘链接。
3. 每次 `commit` 的信息写清楚（例如 `week-03: 修复温度单位换算 bug`），未来的你会感谢现在的你。
