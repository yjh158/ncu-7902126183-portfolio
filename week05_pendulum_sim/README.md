### 6.1 意图清晰度反思

第一次让 AI 编写单摆模拟器代码时，结果不符合预期。回看提示词，只说了"写一个单摆动画"，**缺少验收标准**：

- 没有规定要支持可调节摆长、重力、阻尼；
- 没有要求实时显示角度、周期数据；
- 未明确边界条件（摆绳不可压缩、小球不能穿透画布）。

**后续补齐提示词**后代码符合预期，补齐的四项要素是：

| 要素 | 补齐内容 |
| :--- | :--- |
| **角色** | 前端物理仿真工程师 |
| **目标** | 制作交互式单摆物理模拟器 |
| **约束** | 使用 HTML + Canvas，用单摆微分方程求解，**不使用简单三角函数假模拟** |
| **验收标准** | 可拖动小球释放、参数滑块可调、实时输出物理量、小球碰撞边界不会穿出画布 |

> 💡 **方法论沉淀**：给 AI 的提示词 = 角色 + 目标 + 约束 + 验收标准。四要素缺一，产出就会漂移。

### 6.2 闭环控制反思

遇到动画停滞、小球运动异常报错时，我先**拆分定位**：

1. **看控制台报错** → 判断是语法问题，还是物理计算溢出；
2. **注释掉渲染代码，单独运行物理迭代逻辑** → 判断问题出在渲染循环，还是物理公式。

AI 给出的修复方案我已看懂：

- 原代码使用**小角度近似公式**（`sinθ ≈ θ`），大角度下严重失真 → 修改为**单摆完整微分方程** `θ'' = -(g/L)·sinθ`；
- 增加**边界条件**：限制摆绳长度固定、小球位置不得超出摆长约束；
- 增加**阻尼项**，防止数值积分发散 → 解决动画抖动停滞。

> 💡 **方法论沉淀**："渲染 vs 物理"分层排查。物理对不对看**能量守恒**，渲染对不对看**帧循环**——本实验最终能量漂移 `0.0000%`，说明积分器是稳的。

### 6.3 主体地位确认

**由我（人在回路 · 总设计师）决定的核心决策：**

- 确定产品目标：交互式单摆物理模拟器；
- 选定技术栈；
- 定义仿真的物理模型（是否加入阻尼、是否用小角度近似）；
- 确定交互功能清单（滑块调参、拖拽释放）；
- 确定验收标准，判断 AI 输出结果是否合格。

**由 AI 完成的重复劳动：**

- 编写 Canvas 绘图与 `requestAnimationFrame` 动画循环代码；
- 编写滑块绑定变量的前端交互代码；

- 修复代码语法错误、调试渲染细节，生成页面基础样式。

> 💡 **方法论沉淀**：人负责"做什么、做到什么算合格"，AI 负责"怎么把它写出来"。决策权在我，实现权交给工具。
